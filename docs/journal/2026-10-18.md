## 会议记录机器人：架构再分析（实时流式 + 说话人分离）

作者新想法：Chan Stack（CoreS3 双麦）录音，实时上送飞书 ASR，屏上显示；问是否过阿里云网关；问 ASR 能否区分说话人。

### 核实到的关键事实
- **飞书有独立流式 ASR**：`POST /open-apis/speech_to_text/v1/speech/stream_recognize`，PCM_S16LE/16k/单声道，200–300ms 分片、base64、sequence 递增、is_end 结束，返回 text + start_time/end_time。**之前"妙记非流式"仍成立，但飞书另有流式识别 API，实时字幕可行。**
  - ⚠️ 社区二手资料字段名/分片大小不一致（speech_id vs stream_id；3200B vs 200–300ms），须以官方文档为准，P0/P1.5 先跑通。
- **妙记**：异步文件进/纪要出；声纹分人 10 人内 ~95%+，可关联飞书昵称、可手改。
- **阿里云**：`paraformer-realtime-v2` 实时但不支持 diarization；`paraformer-v2` 文件识别支持说话人分离（`diarization_enabled=true`，回 `speaker_id`，建议 ≤2h）。

### 结论
1. **必须过阿里云 ECS 网关**。理由排序：密钥安全（设备零密钥）> 协议隔离（设备简单流，网关做飞书 300ms 分片+token 刷新）> 断网兜底（缓存补传）> 会后分人/纪要 > 可运维。性能不是理由（多一跳 ~几十 ms 可忽略）。
2. **实时"出字"与"分人"不可兼得**：飞书流式只回 text 无 speaker_id。架构分两层：
   - 实时层：stream_recognize（或 paraformer-realtime-v2）→ 屏上滚字。
   - 会后层：整段音频走妙记 / paraformer-v2(diarization) → 分人逐字稿 + LLM 纪要 → 飞书推送。
3. 实时知道"谁在说"需自建声纹聚类，成本高、不稳，不做 P0/P1。

## 18:00 定案：飞书免费版放弃流式 ASR，改阿里云百炼

作者指出自己是飞书免费用户，ASR 流大概率不支持。核实结论：

- **飞书基础免费版额度（官方 2024-12 权益表）**：妙记转写 **300 分钟/用户/月**（会议录制/录音/本地文件/云文件导入四场景合计，≈5 小时）；**API 1 万次/租户/月**；会中字幕不占额度但上传文件生成妙记要占。
- 实测 `99991400 frequency limit` 与此吻合——不是没权限，是配额压着。**决定：实时层不用飞书 stream_recognize。**
- **阿里云百炼价格（关键）**：
  - `paraformer-realtime-v2` 0.00024 元/秒 = **0.864 元/小时**，每月 **36000 秒（10 小时）免费**，每月 1 日发放。
  - `paraformer-v2` 文件识别 0.00008 元/秒 = **0.288 元/小时**，同样每月 10 小时免费。
  - `fun-asr-realtime` 0.00033 元/秒 = 1.188 元/小时（备选）。
  - 老 ISI 实时 3.50 元/小时、一句话识别 3.50 元/千次 —— **贵 4 倍，不用**。
  - 结论：个人会议场景（每月 10h 实时 + 10h 文件）基本等于免费，比飞书 5h 额度更宽松。
- **ECS 实况**：`i-2zejfwwf1jkyv4cp3grm`，cn-beijing，**未绑定 RAM 实例角色**（元数据 404），故需 `DASHSCOPE_API_KEY` 环境变量，或后续绑 RAM 角色免 AK。

## 18:15 百炼 ASR 实测跑通（实时 WebSocket）

作者提供百炼 API Key（`sk-ws-` 前缀，116 字符），已写入 `.env` 的 `DASHSCOPE_API_KEY`，未回显。

### 实测结论（全部通过）
- Key 有效：OpenAI 兼容 `/compatible-mode/v1/models` 返回 200，176 个模型。
- **通用域名 `dashscope.aliyuncs.com` 直接可用，不需要 Workspace ID**（`DASHSCOPE_WORKSPACE_ID` 留空即可）。
- 文件识别 `POST /api/v1/services/audio/asr/transcription`（`X-DashScope-Async: enable`）返回 200 + task_id，模型 `paraformer-v2` 被接受。
- **实时识别 `paraformer-realtime-v2` 端到端通**：WS 握手 → `run-task` → 3200B/100ms 分帧推流 → `finish-task` → 出字。
  - 测试音频：macOS `say -v Tingting` 生成 5.3 秒中文，`afconvert` 转 16k/mono/s16le。
  - 识别结果一字不差：「这是一段用于测试的会议发言，我们今天讨论三个议题。」

### 关键实现坑（必须写进网关和固件）
- **`sentence.text` 是累积式的**：同一 `sentence_id` 每次回传整句当前全量，直接拼接变复读机。必须按 `sentence_id` 覆盖，`sentence_end=true` 为定稿。
- 字段：`sentence{sentence_id, begin_time, end_time, text, channel_id, speaker_id, sentence_begin, sentence_end, words[]}`；`words[]` 带逐字时间戳（可做打点对齐）；`speaker_id` 恒 null（实时不分人，符合既定决策）。

## 19:10 调研 Chan 官方固件架构（是否做成官方 app）

作者要求：先摸清官方出厂固件的功能/架构/GitHub 更新，再判断会议记录是否该做成官方框架下的应用。

### 一、官方固件事实（m5stack/StackChan）
- 技术栈 **ESP-IDF v5.5.4 + CMake（C++）**，不是社区版的 Moddable JS（此前网上二手资料混淆，已纠正）。
- 应用框架 **mooncake**：`mooncake::AppAbility`，生命周期 onCreate/onOpen/onRunning/onClose；`apps/` 下有 launcher、ai_agent(小智)、avatar、dance、setup(配网)、app_center、espnow、ezdata，以及 **app_template**（官方二次开发入口）。
- HAL 单例 `GetHAL()`：LVGL 显示（需 LvglLockGuard）、网络、OTA、账号、BLE 配网、IMU、RTC、舵机（servo_init 私有）、App Center。
- App Center 的 `launchApp(firmwareUrl)` 下载的是**整包固件**并走 OTA 切换，不是插件热加载；**无公开第三方上架入口**。
- 版本：固件主线到 v1.4.1（2026-05-13），firmware 最近提交 2026-08-19（ILI9342E 屏支持）；app v1.1.4（2026-04-29）；仓库**无 GitHub Releases**，README 声明更新滞后于发布固件。
- StackChan-BSP（Arduino 用）示例只有 Servo/RGB_LED/TouchSensor/IR/NFC/INA226，**没有音频示例**。

### 二、决定性卡点
`hal.h` 音频段只有 `startMicTest()`（3 秒回放）、`getMicWaveformFrame()`（128 点波形）、音量控制，**没有连续 PCM 流**。连续录音被小智 SDK 的 AFE/VAD/唤醒词管线独占。要做会议记录只能：
1. 绕开小智，直接 `GetAudioCodec()->EnableInput/InputData`（可行，但要处理 codec 抢占 + 双麦参考通道）；
2. 改小智音频回调分流 PCM（动 vendor SDK，升级冲突）。

### 三、路线结论
- A 官方 app：能复用配网/OTA/舵机，且能与 AI 助手共存；但要 IDF 5.5.4（本机 6.0.1 不兼容）+ UI 全重写 LVGL + 绕音频管线。
- B 独立 Arduino 固件（现状）：音频完全掌控、UI 已写，但无官方能力复用、不能与助手共存。
- C Arduino + 官方 BSP：推荐。现有代码不变，舵机/灯/触摸复用官方封装。
- **建议短期 C，产品化再评估 A。反转前提：作者要求"平时当 AI 宠物、开会切会议记录"。**
